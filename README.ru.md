# Как работают языковые модели — наглядно

**Демо онлайн:** <https://atdtn.github.io/llm-howto/>

Языки: [English](README.md) · **Русский** · [Deutsch](README.de.md)

Интерактивное объяснение без формул — о главной идее, на которой держатся чат-боты, переводчики и автодополнение в телефоне: **языковая модель — это машина, которая угадывает следующее слово.** Всё остальное — детали этого угадывания.

Страница состоит из девяти коротких разделов. В каждом есть небольшая демонстрация, которую можно потрогать руками: идеи видно в работе, а не нужно принимать на веру.

## Что внутри

| № | Раздел | Идея |
|---|--------|------|
| 01 | Угадай слово | Модель для каждого возможного следующего слова называет вероятность. |
| 02 | Токены | Текст режут на кусочки (токены), и модель работает с их номерами. |
| 03 | Контекст | Смысл слова берётся из соседних слов и хранится как набор чисел. |
| 04 | Внимание | Каждое слово «смотрит» на другие и решает, какие из них важны для его смысла. |
| 05 | Токен за токеном | Ответ собирается по шагам, и на каждом шаге модель перечитывает всё написанное. |
| 06 | Температура | Ручка, которая задаёт, осторожно или смело модель выбирает следующий токен. |
| 07 | Обучение | Вероятности никто не прописывает вручную: их подстраивает обучение. |
| 08 | Устройство | Этапы работы модели и то, как её размер зависит от слоёв и ширины. |
| 09 | И это всё? | Тот же принцип в огромном масштабе и причина, по которой модель иногда звучит убедительно, но ошибается. |

## Для кого

Для тех, кто каждый день пользуется языковыми моделями и хочет понимать, что происходит внутри, без линейной алгебры и подготовки по машинному обучению.

## Языки

Сайт доступен на четырёх языках, и у каждого свой адрес:

| Язык | Адрес |
|------|-------|
| English (по умолчанию) | `/` |
| Slovenčina | `/sk/` |
| Русский | `/ru/` |
| Deutsch | `/de/` |

Переключатель вверху страницы ведёт между ними. У каждого языка свой текст и свой встроенный корпус, поэтому демонстрации работают со словами, естественными для этого языка. У немецкой версии, например, свои сказки, своя карта слов и свои умлауты.

Язык браузера учитывает только корень сайта `/`: при первом заходе читатель, у которого браузер предпочитает словацкий, русский или немецкий (чешский считается словацким), ещё до отрисовки попадает на страницу этого языка. Язык, выбранный в меню, запоминается и важнее языка браузера. Все остальные адреса всегда показывают один и тот же язык — так это нужно поисковикам и ссылкам.

### Как устроены переводы

- `src/index.html` — структура страницы. Текст помечен атрибутами `data-i18n` с именем ключа.
- `src/js/i18n/en.js`, `ru.js`, `de.js` и `sk.js` — словари: текст страницы, строки демонстраций, примеры данных и корпус каждого языка.
- `scripts/build.js` создаёт отдельную статическую страницу на каждый язык: он подставляет переведённый текст, поэтому содержимое уже в HTML, а не добавляется JavaScript'ом.
- `src/js/i18n.js` — небольшой переводчик для демонстраций в браузере; язык он берёт из атрибута `data-lang` страницы.
- `src/js/tests/i18n.test.js` проверяет, что у всех языков одинаковый набор ключей и плейсхолдеров, так что пропущенный перевод роняет тесты, а не незаметно показывает английский.

Чтобы добавить язык, скопируйте `src/js/i18n/en.js` в `src/js/i18n/<код>.js` и переведите. Затем добавьте код в `LANGS` в `scripts/build.js`, подпись в `languageSwitcher()` там же и новый словарь в списки в `src/js/tests/i18n.test.js` и `src/js/tests/site.test.js`. Тесты покажут, чего не хватает.

## Поисковая оптимизация (SEO)

У каждого языка своя страница, поэтому поисковики могут индексировать все четыре:

- **Статический HTML на каждом языке** — переведённый текст уже в разметке; краулеру не нужно выполнять JavaScript.
- **`<html lang>`** — язык страницы.
- **`rel="canonical"`** на каждой странице.
- **`hreflang`** для `en`, `ru`, `de` и `sk`, плюс `x-default` на английскую страницу.
- **`sitemap.xml`** со всеми языковыми страницами и их альтернативами и **`robots.txt`** с ссылкой на него.
- **Open Graph и Twitter-теги** с переведённым заголовком и описанием, а также **JSON-LD** (`WebSite` и `WebPage` с `inLanguage`).

После первой публикации отправьте sitemap (`https://atdtn.github.io/llm-howto/sitemap.xml`) в Google Search Console и Bing Webmaster Tools, чтобы ускорить индексацию.

## Как устроены демонстрации

Демонстрации намеренно сделаны на **игрушечной** модели, и страница об этом честно говорит:

- Разделы 01, 05 и 06 считают частоты слов во встроенном небольшом корпусе (шаблоны из одного, двух и трёх слов с откатом на более короткие). Это таблица подсчётов, а не нейросеть, но она выдаёт настоящее распределение вероятностей следующего слова — тот же интерфейс, что у большой модели.
- Разделы 02 (токены), 03 (карта слов), 04 (внимание) и 07 (обучение) — иллюстрации. Их числа подобраны для наглядности и не получены из обученной модели.
- Раздел 08 оценивает количество параметров и размер файла по формуле `12 · L · d² + 2 · V · d` при точности fp16. Это приблизительная оценка.

Всё работает в браузере. Сайт — это обычные HTML, CSS и JavaScript; единственный шаг сборки создаёт страницы языков.

## Запуск локально

Соберите сайт (появится папка `dist/` с отдельной папкой на каждый язык):

```bash
node scripts/build.js
```

Затем раздайте `dist/` любым статическим сервером, например:

```bash
python3 -m http.server 8000 -d dist
```

и откройте <http://localhost:8000>. Важно открывать через HTTP: переключатель ведёт на папки вроде `/ru/`, которые `file://` не открывает.

### Тесты

Логика ядра (токенизатор, модель на n-граммах, температура, генерация, иллюстрация обучения, оценка размера), переводы и собранные страницы (canonical, hreflang, sitemap) покрыты юнит-тестами на встроенном тестовом раннере Node. Нужна Node 22 или новее (в CI — Node 24).

```bash
node --test src/js/tests/*.test.js
```

## Публикация

Демо публикуется на GitHub Pages через `.github/workflows/pages.yml`: при каждом push в `main` сначала запускаются тесты, затем `scripts/build.js` собирает `dist/`, и публикуется только эта папка. В настройках репозитория один раз укажите **Pages → Source: GitHub Actions**.

Адреса canonical и sitemap используют `https://atdtn.github.io/llm-howto/`. Для другого адреса задайте `SITE_URL` при сборке, например `SITE_URL=https://example.org/ node scripts/build.js`.

## Структура проекта

```
src/index.html          Шаблон страницы; текст помечен ключами data-i18n
src/styles.css          Стили
src/logo.svg             Логотип сайта (он же иконка)
src/js/theme.js         Настройки оформления: режим (авто/светлая/тёмная) и палитра; запоминаются в браузере
src/js/nav.js           Шапка: меню разделов, подсветка текущего раздела, прогресс чтения
src/og/, src/*.png      Картинки для соцсетей и значки; рисует scripts/render-images.js
src/fonts/              Шрифт названия Onest (лицензия OFL), лежит на самом сайте
src/js/i18n/*.js        Словари: en (основной), ru, de, sk — текст страницы, данные демо, корпус
src/js/i18n.js          Переводчик для демо (язык берётся со страницы)
src/js/model.js         Токенизатор и модель на n-граммах: счёт, предсказания, температура, выбор
src/js/generation.js    Пошаговая генерация текста
src/js/learn.js         Иллюстрация обучения
src/js/params.js        Оценка размера модели
src/js/embeddings.js    Данные карты слов и ближайшие соседи
src/js/main.js          Строит модель по корпусу языка страницы и запускает демо
src/js/demo/*.js        По файлу на каждый интерактивный раздел
src/js/tests/           Юнит-тесты (включая тесты сборки сайта)
scripts/build.js        Сборка dist/: страница на язык, sitemap.xml, robots.txt
scripts/render-images.js  Перерисовка картинок и значков (нужен playwright-core, см. файл)
design/                 Варианты палитр и логотипов (на сайт не попадает)
.github/workflows/      Публикация на GitHub Pages (тесты, сборка, деплой)
```
